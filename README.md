# 卫戍协议：盟约 · 服务器启动器

为 [`sganggs/Stronghold-Protocol`](https://github.com/sganggs/Stronghold-Protocol) 做的**跨平台一键服务器启动器**：
下载 → 装依赖 → 下素材 → 启动服务器 → 实时看日志 → 一键更新，全部在一个小窗口里完成。

支持 **Windows / macOS / Linux**，本身**零依赖**（只用 Node.js 标准库，不需要 `npm install`）。

## 功能

| 分类 | 说明 |
| --- | --- |
| **部署** | 按「版本」运行：每个版本是一份独立、完整的源码检出（原版或任意 fork），互不叠加；素材（约 580 MB）只下载一份，各版本通过目录链接共用 |
| **多版本** | 「版本」页可登记/克隆任意 fork（粘贴仓库地址 + 分支）、收纳本机已 clone 的目录、切换当前版本、分别更新与删除；顶部始终显示当前版本 |
| **从 Release 安装** | 不想装 git、或仓库拉不动时，可直接装官方 / Forge 发好的版本包（源码包 / 精简包 / 完整包）。这些包**自带依赖与前端库，装完不用 npm**；增量更新包与语音包会被标为不可单独安装 |
| **mod 源** | 读社区工坊包仓库（`XiaMo233M/Stronghold-Protocol-Forge-Mods`）的 `mods/index.json`，按里面的 sha256 校验下载并安装。**本站不托管任何包。** Forge 版本原生装进 `workshop/`（全部条目可用）；其它 ≥0.3.0 的版本经引擎自带的 `import-forge` 转成插件（只有部分包能转） |
| **一键启动** | 启动 / 停止 / 重启游戏服务器，实时探测 `/healthz`，就绪后自动打开浏览器，并列出可分享的局域网地址（一键复制） |
| **预设** | 内置「默认 / 单机 / 局域网开黑 / 公网反代 / 服务器复算 / 调试」六套预设，也可保存自己的预设（对应游戏 README 里的 `PORT`、`HOST`、`SP_COMBAT`、`SP_VERIFY`、`TRUST_PROXY`、`DEBUG`） |
| **模组（旧）** | 按补丁叠加模组的老功能，已被「版本 + mod 源」取代；`mods.mjs` 代码保留但界面不再显示 |
| **终端** | 内置实时日志视图：ANSI 颜色、时间戳、按通道过滤（部署 / 模组 / 服务器 / 更新 / 启动器）、自动滚动、导出日志 |
| **更新** | 打开时自动检查**每个版本**（`git ls-remote` / GitHub API 回退），在「版本」页显示各自状态与待更新提交；提交没有变化时会明确跳过依赖与素材同步，不再空转。更新日志按 **Markdown 渲染**（标题 / 列表 / 链接 / 加粗 / 行内代码），不再是原始文本 |
| **启动器自我更新** | 启动器也会更新自己：启动时（控制面板打开之前）检查本项目仓库并快进到最新版本，然后自动重启；也可在「主界面 → 启动器更新」里手动检查 / 更新 / 重启。默认源是公开的 HTTPS 地址，所有用户都能自动更新 |
| **诊断** | 一键运行上游的 `tools/doctor.mjs`，检查端口、防火墙、素材完整度；可打开安装目录 / 启动器目录 |
| **关于** | 开发信息、项目链接、完整更新历史与免责声明 |

## 环境要求

- **Node.js 22 或更高**（22 / 24 LTS）。启动器和游戏都用它。
  **没装也没关系**：整合包的 `runtime/` 里已经带了 Windows / macOS / Linux 三平台的 Node.js
  官方运行时，`启动器.bat` / `start.sh` 会检测不到就自动装好，然后再启动界面（详见
  [runtime/README.md](runtime/README.md)）。
- **git（可选但推荐）**：有 git 就用增量更新并能显示提交历史；没有也能用，会自动改用压缩包下载。
- 磁盘：素材约 250 MB + 依赖约 125 MB（Node 运行时另占约 164 MB，已包含在整合包里）。

## 快速开始

1. 把本文件夹放到一个路径较短、**不在 OneDrive 同步范围内**的位置（例如 `C:\Stronghold-Launcher`）。
2. 启动：
   - **Windows**：双击 **`启动器.bat`**
   - **macOS**：双击 **`启动器.command`**（首次若被拦截，右键 →「打开」；或 `bash start.sh`）
   - **Linux / 手动**：`./start.sh`
   - 如果电脑上没装 Node.js，脚本会先自动装好再用它启动界面 ——
     Windows 会打开自带的 `.msi` 安装程序；macOS / Linux 会直接把便携版解压到
     `runtime/node/`（**不需要管理员权限**）。
3. 浏览器会自动打开控制面板（默认 `http://127.0.0.1:7878`）。控制台窗口**不要关闭**——它就是启动器本体。
4. 在「主界面」选一个下载源 → 点 **一键部署** → 等待完成 → 点 **启动服务器**。

> 关闭控制台窗口（或按 `Ctrl+C`）会同时停止启动器和它启动的游戏服务器。

命令行参数：`node launcher/index.mjs [--port 7878] [--no-open]`，也可用环境变量 `SP_LAUNCHER_PORT`。

## 界面说明

### 主界面
- **部署状态**：部署情况、依赖、前端库、素材完整度（按 `data/assets.json` 抽查）、占用空间、运行状态、端口、安装目录。
- **一键操作**：`一键部署 / 补全部署 / 修复安装`、`启动服务器`、`停止服务器`、`重启`、`打开游戏页面`、`打开安装目录`；二级操作：`修复安装`、`只装依赖`、`只下素材`、`环境诊断`。
- **下载源**：切换下载源，点「测试连通性」会并发测速并给出每个源的延迟。
- **分享给朋友**：服务器运行时列出局域网地址，点「复制」即可发人。
- **更新历史**：`CHANGELOG.md` 各版本条目 + 最近的 git 提交（Markdown 渲染，带标题层级和列表）。
- **启动器更新**：启动器自身的版本、远端版本、当前提交，以及「检查更新 / 更新启动器 / 重启启动器」。更新后会提示重启，重启才会生效。

### 配置
- **启动预设**：点一下即套用；「保存当前为预设」把自己的一套参数存下来。
- **端口与运行模式**：`PORT`、`HOST`、`SP_COMBAT`、`SP_VERIFY`、`TRUST_PROXY`、`DEBUG`，每项都有中文说明。
- **下载与更新**：下载源、素材并发数、打开时是否自动检查更新、**多个版本共用一份素材**（开关）与**共享素材目录**。
- **本地客户端素材（可选）**：**客户端目录**（留空则自动查找常见安装位置）、**部署 / 修复时自动提取**开关，以及 `检测客户端`、`重新提取素材` 两个动作。对应上游 `tools/setup.mjs` 的 `--game` / `--local` / `--no-local`（见游戏的 `docs/DEPLOY.md` 第 6 节）。
- **启动行为与安装位置**：是否自动打开浏览器、是否自动启动服务器、安装目录（留空则用启动器目录下的 `game/`）。

> 改了参数记得点 **保存配置**；端口/监听地址等改动在下次启动服务器时生效。

### 本地客户端素材（`docs/DEPLOY.md` 第 6 节）

游戏的官方 3D 棋盘贴图、部分官方界面图标、灼热／炽焰源石虫模型和 39 个召唤物模型来自**本机安装的《明日方舟》客户端**，公开镜像里没有。没有它游戏照常运行，只是 3D 棋盘退化成 2D、部分图标用替代样式。

- **自动检测**：客户端目录留空时，上游 `tools/setup.mjs` 会自己探测常见位置（Windows 原生安装、CrossOver 容器、Wine 前缀、macOS 的 PlayCover）。
- **指定目录**：填客户端里 AssetBundle 的根目录，例如 `…/Arknights_Data/StreamingAssets/AB/Windows`（PlayCover 是 `…/Documents/Bundles`）。填了就优先用这个路径。
- **部署时自动提取**：默认开启。逻辑是——已经提取过就只报告条目数（不重复提取）；没提取过且有客户端才真正提取（需要 Python 3.8+，依赖约 40 MB 装在安装目录的 `.venv-extract`）。关掉它会传 `--no-local`，完全跳过这一步。
- **`检测客户端`**：只探测不写入（`setup.mjs --check`），告诉你找到了哪个客户端、以及它有没有卫戍协议资源。
- **`重新提取素材`**：强制重新提取（`--local`，必要时带 `--game`）——旧的提取结果缺新版模型（例如召唤物模型是 0.2.0 新增的）时用它补上。
- 主界面「部署状态」里有一行「本地客户端素材」，显示已提取的条目数与「3D 棋盘可用」。

> 没有客户端的服务器想要这些官方素材：从**同一版本**的完整整合包里把 `public/assets/local/` 和 `data/local-assets.json` 复制到安装目录的相同位置即可（上游 `docs/DEPLOY.md` §6）。

### 版本（多版本安装）
**每个版本是一份独立、完整的源码检出**（原版或任意 fork），互不叠加——不搞"打补丁"那套，因此也不会有模组互相冲突的问题。

- **添加版本**：粘贴任意 fork 的仓库地址 + 分支即可克隆安装（也支持本机绝对路径）。留空仓库地址 = 用「主界面 → 下载源」里的上游仓库。
- **收纳已下载的目录**：已经自己 `git clone` 好的 fork，填绝对路径就能登记为一个版本，无需重新下载。
- **切换当前版本**：点卡片上的「设为当前」→「启动服务器」即用该版本。服务器运行时不能切换（需先停止）。
- **分别更新**：每个版本按**它自己的**仓库与分支更新（快进合并；上游被改写过时可用强制更新，会丢弃该版本的本地改动）。
- **从 Release 安装**：选一个来源（上游 / Forge）→ 刷新列表 → 点某个资产的「安装」。走这条路**不需要 git**，
  包里的 `node_modules` 与 `public/vendor` 是现成的，装完不跑 `npm`。
  - 资产分三类：**源码包 / 精简包**（不含素材，配合共享区只多下约 25 MB，推荐）、**完整包**（自带约 580 MB 素材）、
    以及**不可单独安装**的（增量更新包只能覆盖某个指定旧版；语音包 / 素材包只有数据；Windows 便携整合包自带 Node 与启动脚本，不经启动器管理）。
  - 这类版本的更新按 **tag** 比对，更新时下载同类型的资产并解压覆盖，**依赖、素材链接、已装的 mod 与服务器状态都会保留**。
  - GitHub API 限流或读不到时，会退回用 git 标签推断列表，并在界面上说明（此时不显示文件大小）。
- **检查更新**：整个「版本」页只有这一套检查机制（原「主界面 → 版本与更新」卡片已并入这里）。打开启动器时自动检查一次，也可随时点「检查更新」；检查只做 `git ls-remote` + 必要的 `fetch`，会列出「待更新提交」。
- **更新时的两个开关**（作用于卡片上的「更新」）：
  - `强制更新（丢弃该版本的本地改动）`：不勾选时只做快进合并，失败会提示；勾选后 `git reset --hard`。
  - `即使没有新提交也重新同步依赖与素材`：默认不勾选。提交没有变化时更新会**跳过** `tools/setup.mjs` 与素材补全（那一步会重新规划约 1.1 万个文件），只提示「已是最新」。
- **删除版本**：只删该版本目录，**共享素材不受影响**；当前版本正在运行时不允许删除。
- **共享素材（默认开启）**：素材（约 580 MB）只下载一份，放在启动器目录下的 `shared/`，各版本的
  `public/assets` 与 `public/fonts` 指向它。N 个版本 ≈ 580 MB + N × 55 MB，而不是 N × 640 MB。
  - 依据：没有任何 fork 把素材文件放进 git（实测 `public/assets` 跟踪文件数为 0），每个 fork 的素材清单都是上游的**超集**（只增不减），且各 fork 新增的路径互不重叠 —— 所以共用一份是安全的并集。
  - 链接方式自动降级：**符号链接 → Windows 目录联接（无需管理员）→ 复制一份 → 不共享**。Windows 上用 junctions，一般不需要开发者模式。
  - **首次把已有安装纳入版本时不会搬动素材**：只登记，界面提示你点「重建素材链接」；那时才把已有素材**移动**（不是重新下载）进共享区并建立链接。
  - 可在「配置 → 下载与更新」关闭共享（每个版本各自下载一份）；关闭后到「版本」页点「重建素材链接」之前不生效。

> 迁移：老版本启动器只有一个 `installDir`，首次启动会自动把它登记为第一个版本（保留原路径），不会重新下载任何东西。

### mod 源
读社区维护的工坊包仓库，按它的目录安装内容包。**启动器不托管、也不缓存任何包的分发**：只读
`mods/index.json`（每条带 sha256、体积、分类，以及引擎真装过一次的结论），再从 `raw.githubusercontent.com`
取 `mod.zip`，**先验哈希再交给引擎安装**。

- **两种装法，由当前版本决定**（页面上会写明）：
  - **Forge 版本** → 引擎原生的工坊包，装进 `workshop/<id>/`，**全部条目可用**，可启停（引擎自己的登记册，重启服务器生效）。
  - **其它 ≥0.3.0 的版本** → 经引擎自带的 `tools/plugin.mjs import-forge` 转成插件，装进 `plugins/<id>/`。
    **只有一部分包能转**：改玩法开关（`behaviour`）、纯主题、接口端点、服务端模块那几类转不了，界面会直接给出引擎的原因。
  - **< 0.3.0**（或没有插件系统的 fork）→ 只能看到提示，装不了。
- **能筛**：全部 / 已装 / 改玩法 / 层 A / 层 B / 层 C + 名称搜索。行上标出体积、文件数、是否含素材，
  并原样展示仓库的备注（含官方素材的包会带 ⚠️ 提示）。
- **卸载**：工坊包交给引擎的登记册（挪进 `workshop/.mod-backups/`，**不是删除**）；插件则删除导入时报告的那些目录。
  只有启动器装过的才可从界面卸载。
- **引擎视角**：「引擎里的清单」把这个版本里引擎自己认到的包打到「终端」，便于对照。
- 目录缓存半小时；下载跟随「主界面 → 下载源」，并带**停滞看门狗**（30 秒没有新字节就换下一个镜像）。

## 启动器自我更新

启动器会更新自己，默认从公开的 HTTPS 仓库拉取：

```
https://github.com/Starst796/Stronghold-Protocol-Server-Launcher
```

> 刻意**不用** `origin`：如果你是用 SSH（`git@github.com:…`）克隆的，那个地址只有你自己的机器能访问，
> 别人就没法自动更新了。默认写成公开 HTTPS，任何人（包括直接下载整合包的）都能更新。
> 想改成自己的源或本地 `origin`，在「配置 → 启动器更新 → 启动器仓库地址」里改（清空则回退用 `origin`）。

1. **启动时自动更新**（默认开启）：在控制面板打开之前、**此时没有任何对局在运行**，检查远端并快进到最新版本，然后自动重启到新版本。
2. **手动更新**：「主界面 → 启动器更新」里有「检查更新 / 更新启动器 / 重启启动器」。
   手动更新后需要重启启动器才会生效；重启会同时停止它启动的游戏服务器，界面会先确认。

安全性：仓库无法访问、没装 git、**本地有未提交的改动**、分支已分叉时，都会**自动跳过并继续用当前版本启动**，
不会阻塞也不会丢改动。只有本地确实落后于远端（能快进）时才会真的更新和重启；本地领先或有未推送提交时
只会在卡片里标注「本地领先于远端」，不做任何操作。启动时那次检查最多等 8 秒（`git ls-remote`），
失败就跳过，所以不会让启动器看起来卡住。

关掉自动更新：「配置 → 启动器更新 → 启动时自动更新启动器」（`autoUpdateSelf`）。
启动器目录不是 git 仓库（例如直接解压的压缩包）时无法自我更新，只会手动提示。

如果整台机器**没有安装 git**（命令不在 `PATH` 里），启动时检测到后会在控制台和网页顶部给出**非阻塞的安装指引**
（含各平台安装命令与下载页面，可一键复制、可「不再提示」），不会阻止你继续用压缩包方式部署游戏。

启动器自己的更新记录见 [CHANGELOG.md](CHANGELOG.md)，在「关于 → 启动器更新历史」里可以直接看。

## 下载源

部分网络无法直连 `github.com`（`git clone` 会超时）。启动器内置多个源，可在「主界面 → 下载源」里**测试连通性**后选择：

| ID | 说明 |
| --- | --- |
| `github` | GitHub 官方地址，海外线路最稳 |
| `ghproxy` | `gh-proxy.com` 加速代理（支持 clone 与压缩包） |
| `ghfast` | `ghfast.top` 加速代理 |
| `ghproxy-net` | `ghproxy.net` 加速代理 |
| `gitclone` | `gitclone.com` 缓存镜像（只支持 clone，更新可能滞后） |
| `gitee-starst796` | `gitee.com` 镜像（Starst796），国内稳定，更新可能滞后 |

素材（约 250 MB 美术 / 音频）下载由游戏自带的 `tools/fetch-assets.mjs` 负责。**它会跟随上面选的源**：`github` / `gitclone` → 直连 GitHub raw（失败时工具自己回退 jsDelivr）；加速源 → `--asset-source=mirror` 并带上对应的代理前缀。在此之上启动器还兜一层：直连下不完时自动改用 GitHub 镜像重试；若素材清单因本地上游索引过期而「将要缩小」（游戏更新新增了干员 / 模型，见 `--refresh-index`），会自动刷新索引后再试一次。

**mod 源也走同一套源**：读工坊包仓库的目录与下载 `mod.zip` 都会优先用当前选中的加速代理，失败再依次试其它公共镜像。

**克隆 fork 也走同一套源。** fork 的地址是用户粘贴的任意 `github.com/作者/仓库`，不是内置源里那一个，所以启动器会把选中的源套到它上面：先试**当前下载源的代理 + 该 fork 地址**，失败再依次试「地址原样（直连）」与其它公共镜像（`gh-proxy` → `ghfast` → `ghproxy.net` → `gitclone`），任一成功即继续。因此选了加速源的用户，即使 `github.com` 完全不通也能安装 fork。细节：

- `git@…` / `ssh://` 地址保持**它自己排第一**（可能带凭据，公共代理用不了），镜像只作后备。
- 已是代理形式的地址（例如上游源里的 `https://gh-proxy.com/https://github.com/…`）不会重复加前缀。
- `gitee.com` / 本机绝对路径 / `file://` 不套代理，原样使用。
- 单次尝试上限 90 秒（被墙的主机不会快速失败，只会耗在系统连接超时上），整条链上限 4 分钟。
- 更新与「检查更新」同样走这条链（`git fetch` / `git ls-remote`），探测用更短的上限（25 秒 / 总共 1 分钟），因为启动时会对每个版本查一次。

## 常见问题

**Q：macOS 双击 `启动器.command` 提示 `bad interpreter: /bin/bash^M`？**
脚本被 Windows 下的压缩/解压工具带上了 CRLF 换行，shebang 于是变成
`#!/bin/bash\r`，系统找不到 `/bin/bash^M`。本仓库已用 `.gitattributes` 固定换行符
（`*.sh`、`*.command` 一律 LF，`*.bat`、`*.cmd` 一律 CRLF），`git clone` 和官方
ZIP 下载不会再有这个问题。若手上的压缩包来自其它途径，在该文件夹里执行下面
一行即可修复（macOS 自带 `perl`）：

```bash
perl -pi -e 's/\r$//' 启动器.command start.sh && chmod +x 启动器.command start.sh
```

修复后仍可双击 `启动器.command`，或在终端里运行 `bash start.sh`。

**Q：电脑上没装 Node.js 怎么办？**
直接双击 `启动器.bat` / `启动器.command` 就行：脚本会优先用 `runtime/` 里自带的安装包
（Windows 打开 `.msi`；macOS / Linux 解压便携版到 `runtime/node/`，不需要管理员密码）；
如果 `runtime/` 里没有对应平台的包，会自动从 nodejs.org 下载。可用环境变量覆盖：

```bat
set SP_NODE_VERSION=v24.21.0
set SP_NODE_MIRROR=https://npmmirror.com/mirrors/node   &rem 国内镜像
set SP_NODE_DRY_RUN=1                                    &rem 只检测不安装（排查用）
```

**Q：怎么确认用的是不是自带的 Node？**
「关于」页会显示「Node 可执行文件」的完整路径 —— 指向 `...\runtime\node\bin\node` 就是自带的便携版。

**Q：启动器会不会把我改过的代码覆盖掉？**
不会。启动时自动更新用的是 `git merge --ff-only`：只要本地有**未提交的改动**或分支已分叉就会失败并自动跳过，继续用当前版本启动。
只有你手动勾选「强制更新（丢弃本地修改）」时才会 `git reset --hard`。

**Q：不想让启动器自动更新自己？**
「配置 → 启动器更新」里关掉「启动时自动更新启动器」。也可以在那张卡片里改仓库地址（默认是公开的 HTTPS 地址，清空则回退用本地仓库的 `origin`）。

**Q：`一键部署` 卡在 `git clone` 或很慢？**
换一个下载源（「主界面 → 下载源 → 测试连通性」挑延迟最低的），再点「修复安装」。

**Q：朋友连不上？**
用「环境诊断」看防火墙和网络类型；Windows 首次启动请在弹窗里勾选「专用网络」并允许。访客 Wi-Fi 常见的 AP 隔离也会导致连不上。

**Q：素材下载中断了？**
直接再点「修复安装」或「只下素材」，会自动续传。

**Q：更新时提示本地有改动？**
你改过安装目录里的文件。确认不需要后，勾选「强制更新（丢弃本地修改）」再更新。
如果是在「模组」页启用了模组，先在那里点「还原为原版」，再更新。

**Q：想装社区 fork 的客制化功能（例如莱茵生命扩展）？**
去「模组」页勾选后点「应用所选模组」。启动器只从**本项目自己的中转仓库**读取模组，不会直接下载第三方
fork 的代码；每个模组都是针对一个固定上游版本打好的补丁，所以**上游发新版后需要等中转仓库重新打包**。
需要安装目录是 git 检出（压缩包解压的安装不行），并且本机要有 `git`。

**Q：「模组」页是空的 / 显示「中转仓库里还没有模组」？**
点「刷新目录」重试；确认网络能访问 `raw.githubusercontent.com`（会自动尝试公共加速镜像）。若你自己维护
一份目录，可在「配置 → 下载与更新」把「模组中转仓库」改成你的仓库地址或直接指向 `index.json` 的 URL。

**Q：想用官方 3D 棋盘 / 官方界面图标？**
在「配置 → 本地客户端素材」填上本机《明日方舟》客户端的 AssetBundle 根目录（或留空让它自动查找），
再点「重新提取素材」；之后「检测客户端」可以确认是否找到。需要 Python 3.8+，提取只在本机使用。
没有客户端的服务器可以从同一版本的完整整合包里复制 `public/assets/local/` 与 `data/local-assets.json`。

**Q：不想提取本地客户端素材？**
关掉「配置 → 本地客户端素材 → 部署 / 修复时自动提取」即可，启动器会给上游的 `setup.mjs` 传 `--no-local`。

**Q：想装某个社区 fork（例如莱茵生命）？**
「版本」页 → 粘贴该 fork 的仓库地址与分支 → 克隆并安装 → 设为当前 → 启动。素材会复用共享区，不会重复下载 580 MB。

克隆过程中启动器会**按当前下载源自动选路**：先试该源的代理，再试直连，最后试其它公共镜像，所以直连 `github.com` 不通也能装。若最后仍然失败，错误里会写明试过几个地址；报错说「找不到分支或标签」则是分支名写错（例如默认分支是 `main` 而非 `master`），与网络无关。

**Q：不想装 git，或者 `git clone` 一直失败？**
用「版本」页的**从 Release 安装**：它下载的是官方 / Forge 打好的 zip，不需要 git，也不需要 `npm`。选「源码包」或「精简包」最省流量。

**Q：怎么装 mod（工坊包 / 插件）？**
「mod 源」页 → 选包 → 安装。工坊包在 Forge 版本上是原生的；如果你现在装的是上游或别的 fork（≥0.3.0），
会经引擎自带的转换器变成插件，**只有一部分包能转**，转不了会在日志里写明原因（通常是它改的是引擎写死的行为开关或只用界面主题）。

**Q：mod 源是谁在托管？会不会收费？**
不是我们。包由社区仓库 `XiaMo233M/Stronghold-Protocol-Forge-Mods` 维护，启动器只读它的目录并按 sha256 校验。
全部是非官方同人内容，**禁止商业使用**；含官方素材的包版权归鹰角网络。

**Q：磁盘占用比预期大？**
每个版本自身约 55 MB（源码 + 依赖），素材只算一份（约 580 MB，在 `shared/`）。若「共享素材」显示"未共享"，
到「版本」页点「重建素材链接」。关掉共享开关则每个版本各存一份。

**Q：切换版本后游戏数据会串吗？**
不会：每个版本有自己完整的 `data/`、存档与配置；共享的只有美术/音频素材。

**Q：自己的模组搞坏了服务器？**
在「模组」页点「还原为原版」即可回到干净的上游版本（模组新增的文件会被删除，你自己的未跟踪文件不受影响）。

**Q：想直接用已有的项目目录？**
「配置 → 安装位置」填上已有目录（例如 `D:\gits\Stronghold-Protocol`），保存即可接管，不会重新下载。

**Q：启动器窗口关不掉 / 想彻底退出？**
关闭控制台窗口或按 `Ctrl+C`；也可以访问 `POST /api/quit`。退出时会连带停止它启动的游戏服务器。
